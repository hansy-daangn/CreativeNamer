# 파일명 일괄 변경기 (Creative Namer)

설치 없이 **웹 주소 접속만으로** 내 컴퓨터의 파일 이름을 규칙에 맞게 일괄 변경하는 정적 웹앱입니다.
파일은 어디에도 업로드되지 않으며, 모든 처리는 브라우저 안에서 로컬로만 일어납니다.

원본 도구(`renamer.bat` + `renamer.ps1`, PowerShell 로컬 서버 방식)를 **브라우저 단독으로 동작하는 순수 웹앱**으로 재구성한 버전입니다.

**접속 주소:** https://hansy-daangn.github.io/CreativeNamer/

## 사용법

1. 위 사이트 주소로 접속합니다.
2. **＋ 파일 선택** 버튼을 누르거나, 파일을 화면에 **드래그앤드롭**합니다.
   - 처음 추가할 때 브라우저가 "파일 수정 허용?"을 **한 번** 물어봅니다. 허용하면 이후엔 추가로 묻지 않습니다.
3. 구분 / 서비스 / 소재명 등을 선택·입력하면 하단 미리보기에 새 파일명이 표시됩니다.
4. **이름 바꾸기** 버튼을 누르면 끝. 추가 클릭 없이 로컬 파일 이름이 바로 바뀝니다.

생성 규칙: `타입_구분_서비스_소재명_해상도_YYMM.확장자` (비어 있는 항목은 자동 생략)

## 동작 원리 / 제약

- **File System Access API** (`showOpenFilePicker`, 드래그앤드롭 `getAsFileSystemHandle`, `FileSystemFileHandle.move()`)를 사용해
  브라우저가 직접 로컬 파일을 제자리에서 이름 변경합니다.
- 해상도(가로x세로)는 이미지/영상 헤더를 브라우저에서 직접 파싱해 채웁니다.
  (mp4·mov·webp·heic 등은 바이트 파서, 그 외 일반 이미지는 브라우저 디코더 사용. 일부 포맷은 해상도를 못 읽을 수 있습니다.)
- **지원 브라우저: Chrome / Microsoft Edge (Chromium 계열).** Firefox·Safari는 이 API를 지원하지 않아 동작하지 않으며,
  접속 시 안내 배너가 표시됩니다.
- 소재명·접두어·구분 프리셋은 브라우저 `localStorage`에 저장됩니다.

## 배포 (GitHub Pages)

이 저장소에는 `.github/workflows/deploy-pages.yml` 가 포함되어 있어, 해당 브랜치에 푸시되면 자동으로 Pages에 배포됩니다.
Pages 소스는 **Settings → Pages → Source: GitHub Actions** 로 설정되어 있어야 합니다.

# 윈도우 네이티브 앱 (확인창 없이 즉시 변경)

웹 버전과 **똑같은 화면**을, 윈도우 전용 프로그램으로도 받을 수 있습니다.
네이티브 앱에서는 브라우저 보안 모래상자가 없어서 **권한 확인창·저장 확인창이 전혀 뜨지 않고**, 어디서 끌어온 파일이든 자유롭게 드래그앤드롭해서 **곧바로** 이름이 바뀝니다.

- 같은 `index.html`을 **[Tauri](https://tauri.app) v2** 껍데기로 감싼 것입니다. 화면을 그리는 엔진은 윈도우에 기본 내장된 **WebView2(Edge/Chromium)** 라서 웹 버전과 픽셀 단위로 동일합니다.
- 파일 입출력만 Rust(`src-tauri/`)가 처리합니다. 이름 변경은 같은 폴더 안의 `std::fs::rename` 이라 **물어볼 권한 자체가 없어** 확인창이 뜰 수 없습니다.
- 파일 크기는 **약 3~10MB** 로 작습니다(크롬을 통째로 내장하는 Electron 대비 1/20 수준).

## 설치 (처음 한 번만 / 컴맹 기준)

저장소 **Releases** 페이지에서 둘 중 하나를 받습니다.

| 형태 | 파일 | 사용법 |
|---|---|---|
| **무설치형(가장 간단)** | `파일명변경기_포터블.exe` | 파일 1개를 받아 **더블클릭** 하면 끝. 설치 과정 없음. |
| **설치형** | `파일명 일괄 변경기_..._x64-setup.exe` | 더블클릭 → 다음 → 설치 → 완료. 시작메뉴 아이콘이 생기고, WebView2가 없으면 자동 설치합니다. |

> 💡 최신 윈도우(10 22H2 / 11)에는 WebView2가 이미 깔려 있어 **무설치형도 대부분 바로 실행**됩니다. 혹시 실행이 안 되면 설치형을 받으세요.

### ⚠️ 첫 실행 때 파란 경고창이 떠도 정상입니다

서명되지 않은 프로그램이라 **처음 1회만** "Windows의 PC 보호" 파란 창이 뜹니다.

1. 작은 글씨 **추가 정보** 를 누릅니다.
2. 나타나는 **실행** 버튼을 누릅니다.

(백신이 막으면: exe 우클릭 → **속성** → 아래쪽 **차단 해제** 체크 → 확인 후 다시 실행)

> 이 경고를 아예 없애려면 코드 서명 인증서가 필요합니다(유료 / 선택). `release.yml`에 서명 키만 추가하면 됩니다.

## 사용법

웹 버전과 동일합니다. 파일을 창에 **끌어다 놓거나** `＋ 파일 선택`을 누르고, 구분/서비스/소재명을 고른 뒤 **이대로 바꾸기 →** 를 누르면 **즉시, 확인창 없이** 바뀝니다.

## 소재명 저장 · 공유 (서버 없이 파일로)

소재명은 서버 대신 **내 PC의 텍스트 파일**에 누적됩니다.

- 저장 위치: `%APPDATA%\파일명변경기\`
  - `materials.jsonl` — 소재명 마스터 목록 (이름 바꿀 때마다 한 줄씩 자동 추가)
  - `inbox\` — **공유받은 파일을 여기에 넣으면** 다음 실행 때 자동으로 합쳐집니다 (처리된 파일은 `inbox\_merged\` 로 이동)
  - `exports\` — `내보내기` 버튼으로 만든 공유용 파일이 저장되는 곳
- 앱 화면 오른쪽 위 **소재 폴더** 링크를 누르면 이 폴더가 탐색기로 열립니다.

**공유하기**: `내보내기` 버튼 → 생긴 `소재목록_YYMM.jsonl` 파일을 카카오톡/메일로 전달.
**받기**: 받은 파일을 `inbox` 폴더에 넣고 앱을 다시 켜면 합쳐집니다. (또는 그 `.jsonl` 파일을 **앱 창에 바로 끌어다 놓아도** 됩니다.)

파일 형식은 한 줄에 하나씩이며, 둘 다 인식합니다.

```jsonl
{"n":"spring","service":"fleamarket","series":"keyword","division":"maugrowth","ts":"2026-06-28"}
{"n":"rent","service":"realty"}
```

```text
# 그냥 이름만 한 줄에 하나씩 적은 .txt 도 됩니다
spring
rent
```

## 빌드 (개발자용)

실제 `.exe` 는 **GitHub Actions의 윈도우 러너**가 만듭니다 — `v`로 시작하는 태그를 푸시하면 자동입니다.

```bash
git tag v1.0.0
git push origin v1.0.0
# → Actions가 빌드해서 Releases에 setup.exe + 포터블 exe 를 올립니다.
```

Actions 탭에서 **Run workflow** 로 수동 실행하면 릴리스 없이 빌드 결과만 Artifacts로 받을 수 있습니다.

로컬에서 직접 빌드하려면(윈도우 + Rust + WebView2):

```bash
mkdir dist && cp index.html icon.svg manifest.webmanifest dist/
cargo tauri build            # 또는: cd src-tauri && cargo build --release
```

`dist/` 와 `src-tauri/target/` 는 빌드 산출물이라 `.gitignore` 처리되어 있습니다.

## 한계 / 참고

- **되돌리기(undo) 없음**: 같은 폴더 내에서만 변경하고, 같은 이름이 이미 있으면 건너뜁니다(기존 `_dupN` 중복방지 유지). 바꾸기 전에 하단 미리보기로 항상 확인됩니다.
- 첫 실행 SmartScreen 1회 클릭(서명 시 제거).
- 매우 큰 영상은 해상도를 못 읽을 수 있습니다(헤더 위치에 따라). 이름 변경 자체는 정상 동작합니다.
- 소재 목록 동기화는 실시간이 아니라 **파일 공유 방식의 수동 동기화**입니다.
